# FoXray Gateway v0.9.15 运维与排障

## 日常检查

```sh
systemctl is-active foxray.service
curl -fsS http://127.0.0.1:18880/api/health
journalctl -u foxray.service -n 80 --no-pager
```

以上为服务器本机检查命令。默认监听 `0.0.0.0:18880`，从其他电脑访问时使用服务器实际 IP；自定义监听时按实际地址和端口检查。先判断管理程序异常还是转发组件异常；控制台短时不可达不代表Xray/WARP/WireGuard已经停止。

检查监控采样、磁盘余量、历史保留、周期检测频率及失败任务。真实缺测显示空白/断点，不能用补零掩盖。

## 备份

节点备份只覆盖节点/订阅范围，不等于完整系统备份。完整备份应包含运行配置、私有目录、数据库、服务配置和需要恢复的系统网络配置；这些文件可能包含凭据，按受限目录保存。

SQLite运行中备份采用数据库原生备份或一致性快照；不要只复制主数据库而忽略WAL。计划维护窗口中停止管理服务再备份可以获得更清晰的一致性，但会暂停管理侧任务与采集，转发是否独立继续须核对实际服务依赖。

保留当前二进制/静态目录与校验值，定期验证能解包和恢复。版本包不含服务器配置、节点凭据与历史数据。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 浏览器打不开 | 监听地址、SSH隧道、管理端口访问名单、防火墙、服务日志 |
| 读取成功但保存403 | 请求Origin/Host是否一致、`FOXRAY_ALLOWED_HOSTS`、反向代理认证和Host转发 |
| 旧界面仍存在 | Ctrl+F5、代理缓存、当前`web`链接；不要只替换入口HTML而保留旧资源集合 |
| 图表无数据 | 总开关/指标开关、真实采样是否开始、写入间隔、查询范围、时间与磁盘状态 |
| 检测失败但接口UP | 管理状态UP不等于端到端可达；查路由、目标、DNS及探测配置 |
| WireGuard汇总橙色 | 部分接口正常，按全部接口汇总，不只看当前页面 |
| 控制台更新但核心没更新 | 管理程序与转发组件独立，这是正常分离；组件更新需单独操作 |
| 默认路由变更后失联 | 立即使用独立管理通道核验计划/回退状态，不反复应用新计划 |
| WARP安装/更新失败 | Cloudflare源、条款接受、系统包管理兼容及官方客户端支持 |

## 故障排查顺序

1. 保留现场状态与只读证据，记录时间和版本，先不重启所有组件。
2. 通过健康接口、systemd状态区分管理服务和转发核心问题。
3. 查看`ip link`、`ip route`、`ip rule`、DNS与`nft`规则；收集后先脱敏再分享。
4. 核对最近任务、变更计划及回退期限，确认是否仍有待确认操作。
5. 若是管理程序升级故障，按升级手册回退程序与web链接；不要同时恢复不匹配的新旧配置快照。

## 更新与清理

更新前核对版本包SHA256、包内清单、配置备份、当前release路径和转发基线。保留至少一个已验证可运行的管理版本。仅在新版本健康且核心PID、VPN、路由和DNS符合预期后清理临时预览或过期构建。

不要批量删除`/opt/foxray/private`、数据库、`/etc/wireguard`或所有旧release。清理日志使用界面保留策略；对运行中的SQLite不要直接删除文件。

问题反馈至少包括：FoXray版本、OS/架构、相关组件版本、复现步骤、预期/实际结果及脱敏日志。禁止公开订阅地址、Cookie、Authorization、私钥和包含账号信息的完整配置。
